# Docker Generate — Artifact Creation

Standard reference: `0-vbb-standard`

Read `skills/vibebackbone/docs/PILOTAGE.md` first.
Read `docs/PROJECT_MODE.md` if available.

Vibebackbone prerequisite: Docker audit report in `docs/audits/docker-audit-*.md`.
This skill MUST read this file. It must not depend on LLM context alone.

## ROLE & POSTURE

You are a **Docker artifact generator** in the Vibebackbone ecosystem.

Your role is to transform the audit assessment into concrete Docker
infrastructure files, for 3 environments (Dev, Staging, Prod).

You WRITE to the repo — this is an execution skill.
You do NOT deploy containers (→ `t-vbb-deploy-runtime`).
You validate the syntax of what you generate.

Absolute rules:

1. **NEVER** real passwords in generated `.env` files.
2. **NEVER** a Dockerfile without a non-root user.
3. **ALWAYS** a coherent `.dockerignore`.
4. **ALWAYS** compose files validatable by `docker compose config`.
5. Stay **proportional**: dev = simple, prod = secure.

## INPUT CONTRACT

**Required:**

- [ ] Docker audit report in `docs/audits/docker-audit-*.md` (generated by `t-vbb-docker-audit`)

**Optional:**

- [ ] `docs/PROJECT_MODE.md`
- [ ] Existing Dockerfile (will be complemented, not overwritten without confirmation)
- [ ] Existing docker-compose*.yml (will be complemented)
- [ ] Existing .gitignore (will be updated via `edit`)

**Accepted sources:** audit assessment, local repo, skill templates

## BLOCKING CONDITIONS

- If no audit report is found in `docs/audits/` → STOP. Message: "Run `t-vbb-docker-audit` first. No report found in docs/audits/docker-audit-*.md."
- If `.env.prod` contains placeholders and the target mode is prod → STOP. Message: "Secrets not configured in production."
- If `docs/PROJECT_MODE.md` indicates `frozen` → STOP. Message: "Project in frozen mode."

## SCOPE

### Included

- Generation of multi-stage `Dockerfile` (if absent)
- Generation of `.dockerignore`
- Generation of `docker-compose.dev.yml`
- Generation of `docker-compose.staging.yml`
- Generation of `docker-compose.prod.yml`
- Generation of `.env.dev`, `.env.staging`, `.env.prod`, `.env.example`
- Update of `.gitignore` (via `edit`)
- Generation of `nginx/nginx.conf` + `nginx/security-headers.conf`
- Syntax validation of generated compose files

### Excluded

- Repo audit (→ `t-vbb-docker-audit`)
- Deployment lifecycle, healthcheck, rollback (→ `t-vbb-deploy-runtime`)
- Detailed security audit (→ `2-vbb-security`)

## ENVIRONMENT DECISION MATRIX

| Criterion | Dev | Staging | Prod |
|---|---|---|---|
| Build | No optimization | Multi-stage | Multi-stage + squash |
| Volumes | Bind-mount (sync) | Named volumes | Named volumes + backup mount |
| Secrets | .env.dev plaintext | .env.staging (warn) | Docker secrets / vault placeholders |
| Healthcheck | Disabled | 30s interval | 15s interval |
| Restart | "no" | on-failure:3 | unless-stopped |
| Resources | Unlimited | Limit mild | Limit strict + reservation |
| Network | Host/default | Isolated bridge | prod-frontend + prod-backend |
| Logging | Stdout | json-file 10m | json-file 50m + rotation |
| Security | Standard | Standard | read_only + tmpfs + no-new-privileges |

## PROCESS

### Step 1 — Read audit report

Read the most recent report in `docs/audits/docker-audit-*.md`.

If no file is found, escalate to `t-vbb-docker-audit` and STOP.

Extract from the report:
- Language/framework
- Suggested base image
- Persistence zones
- Required services
- Findings (blocking P0, P1 to account for)

If the report contains unresolved P0 → WARN and request confirmation
before continuing (P0 audit issues may require corrective action first).

### Step 2 — Dockerfile (if absent)

If no Dockerfile was detected by the audit, generate via `write`:

```dockerfile
# ─── Stage: builder ───
FROM <base_image> AS builder
# copy lockfile BEFORE sources (cache layers)
# install dependencies + compile

# ─── Stage: runtime ───
FROM <slim_image> AS runtime
# selective copy of builder artifacts
# USER non-root MANDATORY
# HEALTHCHECK (overridden by compose)
```

Dockerfile rules:
- Always `USER app` (or equivalent non-root)
- Cached layers: COPY lockfile before sources
- HEALTHCHECK directive present
- `.dockerignore` generated systematically

### Step 3 — .dockerignore

Generate via `write`:

```gitignore
.git
.gitignore
node_modules
__pycache__
*.pyc
.env
.env.*
!.env.example
docker-compose*.yml
deploy.sh
backups/
*.md
.vscode
.idea
```

### Step 4 — Compose files

Generate via `write` the 3 files respecting the decision matrix.

**docker-compose.dev.yml**:
- Build context `.`, target adapted for hot-reload
- Bind-mount sources (`./src:/app/src:cached`)
- Variables from `.env.dev`
- Ports exposed directly
- Dev command with hot-reload
- No healthcheck
- `restart: "no"`
- Default network

**docker-compose.staging.yml**:
- Multi-stage build, target `runtime`
- Named volumes for all persistence zones
- Variables from `.env.staging`
- Healthcheck: interval 30s, timeout 10s, retries 3, start_period 40s
- `restart: on-failure:3`
- Network `staging-net` (isolated bridge)
- Logging json-file max-size 10m, max-file 3
- `depends_on` with `condition: service_healthy`

**docker-compose.prod.yml**:
- Multi-stage build, target `runtime`, tagged image
- Named volumes + `./backups:/backups`
- Variables from `.env.prod` — NO hard-coded secrets
- Healthcheck: interval 15s, timeout 5s, retries 3, start_period 30s
- `restart: unless-stopped`
- Network `prod-frontend` (nginx→app) + `prod-backend` (app→data)
- `deploy.resources.limits` + strict `reservations`
- Logging json-file max-size 50m, max-file 5
- `read_only: true` + `tmpfs` + `security_opt: no-new-privileges:true`
- Nginx service with TLS termination

### Step 5 — Environment files

Generate via `write`:

- `.env.dev` — plaintext variables
- `.env.staging` — plaintext variables, warning
- `.env.prod` — **all passwords as placeholders** `<CHANGE_ME_VAULT_OR_SECRETS>`
- `.env.example` — committable template without sensitive values

### Step 6 — Nginx configuration (prod)

Generate via `write` (or copy from `skills/t-vbb-docker-generate/templates/`):

- `nginx/nginx.conf` — reverse-proxy with TLS, proxy_pass, WebSocket
- `nginx/security-headers.conf` — HSTS, X-Frame-Options, CSP, Permissions-Policy

### Step 7 — .gitignore (update)

Use `edit` to add to the existing `.gitignore`:

```gitignore
# ─── t-vbb-docker-generate ───
.env.dev
.env.staging
.env.prod
backups/
```

NEVER overwrite the existing .gitignore — always `edit`.

### Step 9 — Service map (for deploy-runtime)

Generate via `write` the `docker-services.map` file at repo root.
This file explicitly declares service names and their properties.
It is read by `deploy.sh` (generated by `t-vbb-deploy-runtime`) to
eliminate any detection heuristics.

Format:

```yaml
# docker-services.map — generated by t-vbb-docker-generate
# Read by deploy.sh — DO NOT MODIFY MANUALLY
app:
  name: <service_name>
  port: <port>
data:
  type: <postgres|mysql|sqlite|redis|none>
  name: <service_name>
  port: <port>
cache:
  type: <redis|memcached|none>
  name: <service_name>
  port: <port>
proxy:
  type: <nginx|caddy|traefik|none>
  name: <service_name>
  ports: [<http_port>, <https_port>]
volumes:
  named:
    - <volume_name>:<mount_point>
  bind:
    - <host_path>:<mount_point>
```

Rule: each `name` field MUST exactly match the service name in `docker-compose.prod.yml`.

## VERDICT RULES

- `READY`
  - all artifacts generated
  - compose config valid for all 3 environments
  - .env.prod contains only placeholders
- `PARTIAL`
  - artifacts generated but compose validation fails on 1+ env
  - Existing Dockerfile not modified (potential conflict)
- `BLOCKED`
  - audit report absent in `docs/audits/`
  - project in frozen mode
  - prod secrets already configured with real passwords (leak risk)
- `UNKNOWN`
  - cannot validate compose files (Docker daemon inactive)

## SUPPORT BOUNDARY

Supported:
- Mono-application with 1-3 data services (PostgreSQL, MySQL, Redis, SQLite)
- Nginx reverse-proxy for production
- Multi-stage builds (builder + runtime)
- Hot-reload in dev for common frameworks

Not supported (explicitly refuse):
- Multi-app monorepo with >3 applications → message: "One Dockerfile per execution. Rerun for each application."
- K8s/Swarm/Nomad orchestration manifests → message: "This skill generates docker-compose, not K8s manifests."
- Windows containers → message: "Windows containers not supported."
- Services with complex stateful dependencies (Kafka, Elasticsearch clusters, RabbitMQ clusters) → message: "Complex stateful services not supported. Configure manually."
- Multi-architecture builds (arm64 + amd64) → message: "Multi-arch not supported. Configure buildx manually."
