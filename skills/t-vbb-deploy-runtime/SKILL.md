# Deploy Runtime — Lifecycle & Gates

Standard reference: `0-vbb-standard`

Read `skills/vibebackbone/docs/PILOTAGE.md` first.
Read `docs/PROJECT_MODE.md` if available.
Read `docs/AUDIT_STATUS.md` if available.

Vibebackbone prerequisite: Docker artifacts generated via `t-vbb-docker-generate`
or equivalents present in the repo.

## ROLE & POSTURE

You are a **Docker deployment engine** with built-in safety gates.

Your role is to provide the full operational lifecycle:
deployment, safe shutdown, rebuild, rollback and validation.

You do NOT SCAN the repo (→ `t-vbb-docker-audit`).
You do NOT GENERATE compose files (→ `t-vbb-docker-generate`).
You PROVIDE the runtime and guardrails.

Absolute rules:

1. **ZERO DATA LOSS** — Inviolable law. No destructive operation without integrity-verified backup.
2. **FAIL OPEN = FAIL DANGEROUS** — When the system hesitates, it refuses.
3. **FAILURE TRANSPARENCY** — `bail()` instead of `exit 1`, with explicit message: "no data has been lost".
4. **PROPORTIONALITY** — Prod gates do not apply in dev.

## BLOCKING CONDITIONS

- If no compose file is present → STOP. Message: "No docker-compose file detected. Run `t-vbb-docker-generate` first."
- If no Dockerfile is present → STOP. Message: "No Dockerfile detected. Run `t-vbb-docker-generate` first."
- If `.env.prod` contains plaintext secrets (non-placeholder) → WARN but do not block (secrets are the user's responsibility).
- If `docs/AUDIT_STATUS.md` contains a `BLOCKED` on data-integrity or security → WARN. Message: "Critical BLOCKED audits detected. Risky deployment. Continue only with explicit confirmation."

## SCOPE

### Included

- Generation of `deploy.sh` script with integrity gates
- Full lifecycle: up, down, rebuild, status, backup, logs, rollback, check
- Modes: normal, `--dry-run`, `--check`, `--force`
- Integrity gates built into the script:
  - Backup integrity (gzip -t, SQLite PRAGMA, non-empty content)
  - Backup size vs active data (consistent ratio)
  - Disk space ≥ 200 MB
  - Write test on existing volumes
  - `down --remove-orphans` (ghost container cleanup)
  - Post-down bind mount verification
  - Automatic rollback if healthcheck fails
  - Save current state before any rollback
  - `bail()` — safe exit with "no data lost" guarantee
- Post-generation validation: `chmod +x deploy.sh`
- Dev mode build test

### Excluded

- Repo audit (→ `t-vbb-docker-audit`)
- Compose file and Dockerfile generation (→ `t-vbb-docker-generate`)
- Detailed security audit (→ `2-vbb-security`)
- Dockerfile or compose file fixes (→ `t-vbb-docker-generate`)

## PROCESS

### Step 1 — Verify prerequisites

Confirm presence of generated artifacts:

```bash
ls -la Dockerfile docker-compose.dev.yml docker-compose.staging.yml \
  docker-compose.prod.yml .env.dev .env.staging .env.prod
```

If files are missing, escalate to `t-vbb-docker-generate`.

### Step 2 — Verify Vibebackbone audits

If `docs/AUDIT_STATUS.md` exists, check recommended pre-audits:

- `2-vbb-ops`
- `2-vbb-data-integrity`
- `2-vbb-security`
- `2-vbb-db-robustness`

If a critical audit is `BLOCKED`, display a warning.

### Step 3 — Generate deploy.sh script

Use `write` to create `deploy.sh` from the template:
`skills/t-vbb-deploy-runtime/templates/deploy.sh`

The script reads `docker-services.map` (if it exists) to determine data service names deterministically. If the file is absent, it falls back to detection heuristics (degraded mode with warning).

The script integrates the **safe redeployment cycle order**:

```
1.  Pre-flight checks (env file, placeholders, Docker daemon)
2.  Verify persistent zones
3.  Verify DB (active container)
4.  Backup DB (active container → reliable dump)
5.  Backup volumes (active container)
6.  ⛔ GATE backup integrity (gzip -t, PRAGMA, non-empty content)
7.  ⛔ GATE backup size vs active data (consistent ratio)
8.  ⛔ GATE disk space ≥ 200 MB
9.  Write test on each existing volume
10. down --remove-orphans
11. Post-down check (bind mounts intact)
12. Build
13. up -d
14. Healthcheck + auto rollback on failure
```

**Commands supported by the script:**

| Command | Description |
|---|---|
| `bash deploy.sh <env>` | Full deployment |
| `bash deploy.sh <env> up` | Same, explicit |
| `bash deploy.sh <env> down` | Shutdown with mandatory backup |
| `bash deploy.sh <env> rebuild` | Rebuild without cache |
| `bash deploy.sh <env> status` | Service + volume + disk status |
| `bash deploy.sh <env> backup` | Manual backup |
| `bash deploy.sh <env> logs [service]` | Real-time logs |
| `bash deploy.sh <env> rollback` | Restore N-1 backup |
| `bash deploy.sh <env> check` | Pre-deployment verification |

**Options:**

| Option | Effect |
|---|---|
| `--dry-run` | Full simulation, zero actions |
| `--check` | Alias for `check` action |
| `--force` | Skip interactive `down` confirmation |

### Step 4 — Permissions

```bash
chmod +x deploy.sh
```

### Step 5 — Validation test

```bash
# Compose syntax
docker compose -f docker-compose.dev.yml config
docker compose -f docker-compose.staging.yml config
docker compose -f docker-compose.prod.yml config

# Build test (dev only)
docker compose -f docker-compose.dev.yml build
```

## INTEGRITY GATES (in deploy.sh)

| Gate | What it prevents |
|---|---|
| Backup integrity (gzip -t, PRAGMA) | Deploying on corrupted backup = silent loss |
| Non-empty backup (size + content) | Restoring empty backup = overwriting with nothing |
| Backup size vs active data | Backup 10x smaller = probably corrupted |
| Disk space ≥ threshold (200 MB) | Incomplete write = corruption |
| Volume write test | Starting without write capability |
| Post-down bind mount check | Data vanished after down |
| Auto rollback if healthcheck KO | Leaving a broken service in production |
| Save before rollback | Overwriting even during restore |
| `bail()` instead of `exit 1` | Exit without data safety guarantee |

## VERDICT RULES

- `READY`
  - deploy.sh generated and executable
  - compose config valid for all 3 environments
  - dev build succeeded
  - Vibebackbone pre-audits non-blocking
- `PARTIAL`
  - deploy.sh generated but compose validation fails on 1+ environment
  - dev build fails (Dockerfile to fix via `t-vbb-docker-generate`)
  - Recommended Vibebackbone pre-audits have a `BLOCKED`
- `BLOCKED`
  - compose files absent
  - Dockerfile absent
  - insufficient disk space
  - `AUDIT_STATUS.md` contains a critical `BLOCKED` on data integrity
- `UNKNOWN`
  - Docker daemon inactive (cannot validate)

## SUPPORT BOUNDARY

Supported:
- docker-compose deployment on single machine (bare metal or mono-VM)
- PostgreSQL, MySQL, SQLite, Redis backup/restore
- Named volume and SQL dump rollback
- Healthchecks via Docker HEALTHCHECK
- Nginx reverse-proxy with TLS

Not supported (explicitly refuse):
- Multi-node clusters (Swarm, K8s) → message: "Multi-node orchestration not supported by deploy.sh."
- Docker secrets (Swarm mode) → message: "Docker secrets requires Swarm mode. Use mounted files or external vault."
- Blue-green / canary deployments → message: "Advanced deployment strategies not supported. Deploy manually."
- Private registry with complex authentication → message: "Registry auth not integrated. Configure docker login manually."
