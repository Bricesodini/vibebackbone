Tu démarres une session de travail sur un projet Vibebackbone.

Ton rôle dans cette phase est uniquement de :

1. récupérer le contexte utile,
2. rappeler l’état courant du projet,
3. identifier la voie probable selon `docs/PILOTAGE.md`,
4. attendre ensuite l’objectif précis de la session avant toute exécution.

Consignes :

- `docs/PILOTAGE.md` est la source de vérité du routage.
- Lire en priorité, si présents :
  - `docs/CONTEXT.md`
  - `docs/SESSION.md`
  - `docs/AUDIT_STATUS.md`
  - `docs/PROJECT_MODE.md`
- Si `0-vbb-pilotage` est disponible, l’utiliser comme miroir de la logique de routage avant d’inférer la voie.
- Produire un résumé de session compact :
  - état courant
  - dernière étape connue
  - points ouverts
  - risques ou blocages visibles
  - voie Vibebackbone probable (rapide / structurée / audit / clôture)
- Ne lance aucun skill métier tant que la demande de la session n’est pas explicitement donnée.
- Si le contexte est incomplet, le signaler clairement sans inventer.

Réponds avec :

1. Résumé du contexte récupéré
2. Points ouverts ou inconnus
3. Voie Vibebackbone probable
4. Question finale : “Quel est l’objectif précis de cette session ?”
