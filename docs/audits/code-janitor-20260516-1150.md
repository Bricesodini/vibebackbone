## Findings (priorisés)

### JAN-01 — Duplication copy-paste Claude / OpenCode prompt commands

- **Sévérité :** P1
- **Type :** duplication
- **Fichier :** `setup.sh`
- **Evidence :** Les blocs "5. Claude Code — prompt commands" et "9. OpenCode — prompt commands" sont quasi-identiques (42 lignes chacun, ~95 % identiques). Seuls les noms de variables (`CLAUDE_*` vs `OPENCODE_*`) et le label de provider diffèrent.
- **Risque :** Toute modification du format de commande doit être appliquée deux fois → risque de drift.
- **Effort :** M
- **Action recommandée :** Factoriser en une fonction shell `generate_prompt_commands()` prenant `commands_dir`, `prefix`, `label` comme arguments.

### JAN-02 — Commentaire debug leftover dans bloc Python embarqué

- **Sévérité :** P2
- **Type :** debug-leftovers
- **Fichier :** `setup.sh`
- **Evidence :** Ligne ~300 dans le bloc Python Codex : `# Use rough backup`. Ce commentaire est un reste de rédaction itérative, sans valeur technique pour le lecteur.
- **Risque :** Bruit de lecture ; donne une impression de code non finalisé.
- **Effort :** S
- **Action recommandée :** Supprimer ou remplacer par un commentaire technique pertinent (`# Backup existing file before replacement`).

### JAN-03 — Affichage summary silencieux en cas de prompts skipped

- **Sévérité :** P2
- **Type :** structure
- **Fichier :** `setup.sh`
- **Evidence :** Si des prompts Claude, OpenCode ou Pi sont skipped (fichier custom existant), le warning est affiché en cours de route, mais le section "Prompt adapters" du summary final ne les liste pas explicitement comme skipped. Seuls les compteurs à zéro déclenchent l'affichage du statut positif.
- **Risque :** Le résumé final peut laisser croire que tous les adaptateurs sont installés alors que certains ont été skipped.
- **Effort :** S
- **Action recommandée :** Ajouter une branche `elif` dans le summary pour afficher `⚠ $label: $count skipped` quand le compteur skip > 0.

### JAN-04 — Fragilité `find | grep` dans `tests/smoke-install.sh`

- **Sévérité :** P2
- **Type :** structure
- **Fichier :** `tests/smoke-install.sh`
- **Evidence :** Lignes du type `find "$dir" -name "vbb-*.md" | grep -q .` — si le répertoire n'existe pas, `find` retourne une erreur et le pipe échoue de manière opaque. Le `!` inverse l'exit code, mais le diagnostic est difficile en cas de vrai échec.
- **Risque :** Faux positif / faux négatif silencieux lors du debug du test.
- **Effort :** S
- **Action recommandée :** Utiliser `test -d "$dir" && find ... | grep -q .` ou `[ -z "$(find ... 2>/dev/null)" ]` pour expliciter la condition.
