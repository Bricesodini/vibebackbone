## Technical debt assessment

### TD-101 — P1 — high — Auto-sélection loop-closure incorrecte

- **Evidence** : `python tools/vbb-loop-closure-check.py` sélectionne
  `20260615-usage-audit` et échoue sur la voie `STRUCTURED`; le dashboard classe
  correctement les runs récents par mtime.
- **Why this matters** : le gate local peut contrôler le mauvais run et produire
  un faux blocage ou une fausse assurance.
- **Recommended action** : partager une fonction unique de résolution des runs
  entre dashboard, CI et loop-closure, puis ajouter les cas de noms mixtes.

### TD-102 — P1 — high — Installation des hooks non convergente

- **Evidence** : `scripts/install-framework-gate-hook.sh` installe un fichier
  `pre-commit-framework-gate` que Git n'exécute pas par défaut, tandis que
  `scripts/install-vbb-pre-commit.sh` écrase `.git/hooks/pre-commit` avec une
  autre implémentation moins complète.
- **Why this matters** : l'utilisateur peut croire les gates actifs alors que
  seule une partie est exécutée.
- **Recommended action** : définir un installateur canonique composant les deux
  hooks locaux déjà testés et déprécier l'autre entrée.

### TD-103 — P1 — high — Dette de typage et de propreté non bornée

- **Evidence** : `ruff check tools tests` retourne 36 erreurs ;
  `ruff format --check` voudrait reformater 26 fichiers ; `mypy tools` retourne
  48 erreurs dans 8 fichiers.
- **Why this matters** : QOA-007 est réel et les contrôles optionnels ne donnent
  pas aujourd'hui une baseline stable.
- **Recommended action** : séparer un lot Janitor autofix sûr d'un lot typage
  manuel, sans promouvoir les outils au gate avant baseline verte.

### TD-104 — P1 — high — Executor critique sans test direct

- **Evidence** : aucune référence à `vbb-executor` dans `tests/`; le fichier fait
  631 lignes, contient un `_yaml_load` redéfini et 8 erreurs mypy concentrées sur
  l'état de résultat.
- **Why this matters** : l'executor matérialise la machine d'état et les gates ;
  une régression y contredit les claims de robustesse Core.
- **Recommended action** : caractériser chargement, transitions, erreurs et
  génération d'artefacts avant tout nettoyage interne.

### TD-105 — P1 — high — Portabilité contredite par les docs injectées

- **Evidence** : `AGENTS.md`, `docs/PILOTAGE.md`, `docs/RUNBOOK.md` et
  `docs/LONG_RUN_RULE.md` contiennent `~/02_Dev`; `AGENTS.md` conserve une
  provenance et une prompt library `/Users/bot/...`.
- **Why this matters** : les quatre adaptateurs distribuent une gouvernance qui
  ne doit pas dépendre du HOME du mainteneur historique.
- **Recommended action** : utiliser le dépôt courant / `$VBB_HOME` et documenter
  les prompts comme chemin résolu par setup.

### TD-106 — P2 — high — Fonctions surdimensionnées

- **Evidence** : 36 fonctions dépassent 40 lignes dans 13/14 outils ; pics :
  `vbb-loop-closure-check.main` 218 lignes, `check_run` 182,
  `vbb-context-compactor.compact_run` 145, `execute_contract` 134.
- **Why this matters** : la convention de lisibilité n'est pas mesurable comme
  respectée et les changements transverses deviennent coûteux à reviewer.
- **Recommended action** : prioriser seulement les fonctions critiques déjà
  couvertes par tests ; ne pas lancer un découpage global.

### TD-107 — P2 — high — État d'audit et registre de dette stale

- **Evidence** : QOA-003 est marqué résolu malgré reproduction ; QOA-008 reste
  ouvert alors que `distribution-setup` et le smoke couvrent les quatre
  adaptateurs ; `TECH_DEBT.md` conserve PyYAML « non installé » alors que
  `PyYAML 6.0.2` est disponible et les gates l'utilisent.
- **Why this matters** : la source de vérité de pilotage devient moins fiable que
  les commandes qu'elle résume.
- **Recommended action** : réconcilier uniquement les entrées vérifiées, sans
  réécrire les rapports historiques.
