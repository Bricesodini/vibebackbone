# Scope freeze — credentials enforcement

## Scope écrit

Le run borne l'audit aux scripts de hook, à leur installation, aux tests et à
la définition CI. Il n'autorise ni scanner, ni dépendance, ni modification de
distribution, ni fixture ressemblant à un credential réel.

## Cas d'usage critiques

1. Empêcher qu'un contenu staged manifestement sensible entre dans l'historique.
2. Conserver un contrôle local rapide avant commit.
3. Fournir un filet CI commun lorsque les hooks locaux sont absents ou bypassés.
4. Tester le comportement avec des marqueurs synthétiques sans valeur secrète.

## Non-objectifs

- Garantir l'absence absolue de tout secret par heuristique.
- Scanner les runtimes utilisateur, coffres ou dépôts consommateurs.
- Choisir ou implémenter un moteur de détection pendant ce run d'audit.

## Frontières

- **Core** : invariant, outil partagé éventuel, hook et workflow CI.
- **Distribution** : aucune adaptation spécifique identifiée à ce stade.
- **Externe** : installation effective des hooks et historiques consommateurs.

## Verdict

**READY.** Le scope est explicite, testable et stable. Toute implémentation
doit démarrer dans un nouveau run STRUCTURÉ avec ADR, POC et Integration Gate.
