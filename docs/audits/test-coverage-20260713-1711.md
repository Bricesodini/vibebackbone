# Test coverage — retrait Hermes et support de quatre providers

## Chemins critiques identifiés

| Chemin | Risque | Couverture visible |
|---|---|---|
| Routage de `setup.sh` vers Claude Code, Codex, Pi et OpenCode | provider officiel absent ou mal routé | `tests/test_setup_smoke.sh` vérifie les quatre valeurs de `ALL_PROVIDERS` et les quatre scripts de distribution |
| Rejet du provider retiré | compatibilité Hermes conservée par erreur | smoke négatif + exécution directe de `setup.sh --provider hermes --dry-run --no-interactive` |
| Installation non destructive | écriture involontaire pendant la validation | dry-run séparé pour chacun des quatre providers |
| Gate de commit local | dépendance résiduelle au runtime Hermes ou mauvaise classification des distributions | `tests/test_framework_gate_hook.sh`, 10 scénarios sur les deux hooks locaux |
| Cohérence Core/documentation | chemins supprimés encore déclarés comme actifs | lint architecture, régénération de `docs/RELATIONS.md`, contract lint et scans ciblés |

## Couverture présente

- Le smoke teste la syntaxe, les sources Core, les quatre adaptateurs et
  l'absence d'Hermes sur la surface active de l'installateur.
- Le test des hooks couvre les commits in-scope, out-of-scope, les tables de
  preuve, l'approbation explicite et deux distributions supportées.
- La suite pytest couvre les outils Core modifiés (`gate-check`, loop closure,
  review threshold et status dashboard).
- La CI locale agrège les validations contractuelles et tests Core.

## Gaps prioritaires

1. Aucun test end-to-end ne lance une installation réelle dans les quatre
   runtimes ; les dry-runs couvrent le routage, pas le comportement des outils
   externes installés.
2. Aucun test ne peut détecter un consommateur externe qui importerait
   directement l'ancien proxy Hermes.
3. Le scan de documentation distingue par convention les références actives
   des archives ; il n'existe pas encore de linter sémantique de cette frontière.

## Tests recommandés

1. Ajouter en CI une matrice d'installation sous HOME temporaire pour les
   quatre providers supportés.
2. Ajouter un test contractuel déclarant exactement l'ensemble
   `{claude,codex,pi,opencode}` dans un artefact machine-readable unique.
3. Ajouter un check de liens qui exclut explicitement archives, runs et ADR
   historiques mais interdit les chemins supprimés dans les docs actives.

## Inconnues et limites de preuve

- Les installations existantes sous `~/.hermes/` et les consommateurs externes
  au dépôt ne sont pas inspectés ni modifiés.
- Le fonctionnement des exécutables tiers Pi, OpenCode, Codex et Claude Code
  n'est pas testé ; seule l'intégration produite par Vibebackbone l'est.

## Verdict

`READY` pour le retrait : les risques directs de routage, gate local et
cohérence Core sont couverts. Les gaps restants concernent l'intégration réelle
des runtimes externes et sont bornés, non bloquants pour cette suppression.
