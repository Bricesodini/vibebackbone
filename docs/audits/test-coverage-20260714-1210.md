# Test coverage — layered credentials enforcement

## Critical paths

| Path | Visible coverage | Status |
|---|---|---|
| High-confidence and generic detection | parameterized unit cases | COVERED |
| Placeholder and ordinary-content negatives | parameterized unit cases | COVERED |
| Staged diff blocking and value non-disclosure | temporary Git repo CLI test | COVERED |
| Justified/unjustified exception | positive and negative CLI tests | COVERED |
| Deletion and binary handling | temporary index tests | COVERED |
| Explicit commit range | two-commit CLI test | COVERED |
| Push with zero base | parent fallback and initial-commit empty-tree tests | COVERED |

| Hook integration | versioned hook blocks same staged finding | COVERED |
| Remote workflow execution | YAML parsed; matrix execution occurs after push | UNKNOWN until server run |

## Highest-value tests implemented first

1. Staged sensitive addition blocks without printing the matched value.
2. The canonical hook propagates the scanner failure.
3. Range mode covers normal, zero-base and initial-commit paths.
4. Deletions, binaries, placeholders and environment references do not block.
5. Exception requires a local non-empty `reason=` and remains visible.

## Priority gaps

- Observe the first GitHub Actions run on Linux and macOS after push. This is an
  external execution check, not a missing local test surface.
- Add a regression only when a real false positive/negative is observed; do not
  inflate the pattern list speculatively.

## UNKNOWN / evidence limits

- Future provider token formats are not enumerable in advance.
- Hooks copied into external consumers are outside repository evidence.
- No test can prove absence of all secret forms; manual review remains canon.

## Verdict

**READY.** The critical decision paths are directly covered by 16 focused tests
plus hook and full-suite checks. The remaining unknown is the remote runner
execution, which will be observable only after push.
