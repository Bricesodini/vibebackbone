# Formatter / linter enforcement audit

## Context

**Date**: 2026-07-14 14:10 Europe/Paris
**Scope**: tracked Python under `tools/` and `tests/`
**Inputs**: `docs/CONVENTIONS.md`, latest global janitor report, local/remote CI,
dependency manifests and observed tool output
**Mode**: DEV, read-only audit

The repository supports Python 3.11 in GitHub Actions. Ruff 0.13.1 and mypy
2.1.0 are installed locally but absent from dependency manifests and canonical
configuration. Pyright is absent and has no repository contract.

Observed baseline:

- `ruff check tools tests`: 37 errors, 25 safely autofixable;
- `ruff format --check tools tests`: 29 files would be reformatted, 4 conform;
- `mypy tools --ignore-missing-imports`: 20 errors after executor cleanup;
- neither local nor remote CI invokes these checks.

## Verdict

`READY` — one coherent, low-risk enforcement path exists: Ruff check + Ruff
format + mypy, configured for Python 3.11 and pinned as development tooling.
Pyright should stay outside the supported contract until a distinct need is
demonstrated. Activation must remain non-blocking until the measured baseline
reaches zero.

## Convention → Enforcement map

| Convention | Mechanical enforcement | Initial posture |
|---|---|---|
| readable imports, names and dead-code control | Ruff `E4`, `E7`, `E9`, `F` | measure, then clean |
| one stable Python layout | Ruff formatter, default line length 88 | format in isolated commit |
| explicit interfaces and robust structures | mypy over `tools/` | fix tool by tool |
| one canonical solution | `pyproject.toml` as shared configuration | no parallel config |
| P.R2 and regression prevention | local + GitHub CI only after zero | deferred gate promotion |

## Findings (prioritized)

### FL-01 — Dirty supported baseline

- **Severity**: P1
- **Type**: `ci-gap`
- **Evidence**: Ruff check reports 37 errors, format reports 29 files, mypy
  reports 20 errors; none is in local or remote CI.
- **Risk**: READY cannot prove static-quality convergence and new debt can be
  added unnoticed.
- **Effort**: L
- **Recommendation**: clean Ruff, format and mypy in separate bounded lots,
  then promote all three together after zero is reproducible.

### FL-02 — Tool versions and scope are not reproducible

- **Severity**: P2
- **Type**: `missing-tooling`
- **Evidence**: `requirements.txt` contains only runtime/test dependencies;
  Ruff 0.13.1 and mypy 2.1.0 come from the workstation, with no repo config.
- **Risk**: local and CI results can drift by version or implicit defaults.
- **Effort**: S
- **Recommendation**: add a development requirements manifest with exact
  versions and a single `pyproject.toml` scoped to `tools/` and `tests/`.

### FL-03 — Type checker ownership is undecided

- **Severity**: P2
- **Type**: `config-conflict`
- **Evidence**: historical readiness language names mypy and Pyright, while
  only mypy is installed and exercised; Pyright has no config or distinct use.
- **Risk**: two overlapping type systems could create contradictory fixes and
  double maintenance.
- **Effort**: S
- **Recommendation**: support mypy only; reopen Pyright if editor or consumer
  requirements expose a capability mypy cannot cover.

### FL-04 — Editor behavior is implicit

- **Severity**: P2
- **Type**: `editor-gap`
- **Evidence**: no `.editorconfig` or shared editor configuration is tracked.
- **Risk**: contributors discover formatting only at command or CI time.
- **Effort**: S
- **Recommendation**: document format-on-save as optional after the canonical
  formatter is configured; do not make editor metadata a READY blocker.

## Activation plan (phased)

### Phase 0 — Inventory and safety

Record ADR + approved canon proposal, pin Ruff/mypy, define Python 3.11 scope,
and preserve the measured non-zero baseline without exclusions.

### Phase 1 — Formatter only

Apply Ruff formatting in a mechanical-only commit after lint cleanup, then run
P.R2 to prove behavior unchanged.

### Phase 2 — Linter warn-only

Use canonical local measurement commands while resolving the 37 Ruff and 20
mypy errors. Do not add suppressions solely to reach zero.

### Phase 3 — Strict + CI gate

Once all three commands pass on a clean checkout, add identical checks and
pinned development dependencies to local and GitHub CI. Prove each gate fails
on a controlled violation, then restore green.

## CI / Pre-commit / Editor alignment

- CI: install the pinned development manifest and run the same three commands
  on macOS and Linux only after baseline zero.
- Pre-commit: keep the existing correctness/security hook unchanged during
  cleanup; adding slow global type checking is not required for READY.
- Editor: recommend Ruff format-on-save and diagnostics, but keep repository
  commands authoritative.

## Exceptions policy

An exception must be narrow, code-local, justified, owned and paired with a
removal trigger. Global `ignore_errors`, broad file exclusions, blanket
`noqa`, and rules disabled only because they currently fail are prohibited.
External PyYAML stubs may remain handled by `ignore_missing_imports` until the
dependency contract deliberately includes typing stubs.

## Unknowns / needs confirmation

- Whether consumers need Python versions beyond the CI-supported 3.11 is not
  documented; reopen target-version only when the support matrix changes.
- Editor preferences are user-owned and should not block READY.
- Pyright can be reconsidered if a concrete editor or distribution need appears.
