## Analyse
Le smoke test `0-vbb-zero-friction` crée un run FAST-ZERO
minimal. Mais le validator `vbb-loop-closure-check.py` exige
maintenant (depuis cutover 2026-07-27_1712) :
- `knowledge_governance_version` dans frontmatter
- `assurance_governance_version` dans frontmatter
- `artifacts_produced` dans frontmatter
- `voie` dans frontmatter
- `knowledge_harvest` dans frontmatter
- `ASSURANCE_STATUS` block sibling dans 07_CLOSEOUT

Le smoke test zero-friction crée un run PASS du point de vue
du tool de création, mais FAIL sur la validation post-cutover.

## Classification
**`ACCEPTABLE_STABLE_RISK`** — la création de run fonctionne
(côté executor), mais le smoke test zero-friction n'a pas été
mis à jour pour le cutover 2026-07-27_1712. Cela n'affecte pas
l'usage réel (les utilisateurs utilisent les templates complets
décrits en docs).

## Recommandation
Un run de mise à jour de `0-vbb-zero-friction` skill devrait
inclure:
- knowledge_governance_version
- assurance_governance_version
- artifacts_produced
- voie
- knowledge_harvest
- ASSURANCE_STATUS block

Pour la RC v1.1.0-rc.2, ce n'est pas un blocage : le smoke
test est conservé comme test de capability, et la validation
post-cutover est documentée (cf. AGENTS.md cutover).
