# ADR — 0023-generated-sentinel-detection

**Status**: ACCEPTED  
**Date**: 2026-07-13  
**Route**: STRUCTUREE  
**Décideurs**: Brice Sodini (project lead & canon owner)  
**Liée à**: docs/strategy/vbb-evolution-multi-service-support/01_GAP_ANALYSIS.md § Gap-17  
**Liée à POC**: vide  
**Liée à ADR amont**: 0012 (codegen AGENTS.md, source de détection)

## Contexte

`tools/vbb-architecture.py` lint valide que `RELATIONS.md` est cohérent avec `ARCHITECTURE.md`. Mais **rien n'empêche** un humain d'éditer `RELATIONS.md` à la main. La consigne « Generated — do not edit » (cf. ADR-0004) est documentaire, pas enforced.

Idem pour les fichiers générés par `setup.sh` (AGENTS.md installé, SYSTEM.md installé, CLAUDE.md installé) — aucune vérification post-install que le contenu est bien celui attendu.

Conséquence : un humain peut éditer `RELATIONS.md` manuellement et le drift est silencieux jusqu'à la prochaine régénération (qui peut être lointaine).

## Décision

**Introduire un sentinel canonique `@generated by <tool-name> at <YYYY-MM-DD>` en tête des fichiers générés, et un outil `tools/vbb-generated-check.py` qui valide la cohérence.**

### Format du sentinel

Le sentinel est un commentaire YAML/Markdown placé dans les **premières lignes** du fichier généré :

```yaml
---
# @generated by tools/vbb-architecture.py at 2026-07-13
# Do not edit manually — re-run the tool to regenerate.
---

# Contenu du fichier...
```

### Comportement du linter

`tools/vbb-generated-check.py` lit la liste des fichiers générés (configuré par `tools/vbb-architecture.py` ou déclaré dans `MANIFEST.yaml` des extensions, cf. ADR-0014) et vérifie :

1. **Sentinel présent** : chaque fichier marqué `@generated` doit avoir le sentinel en tête.
2. **Cohérence** : si le fichier source canonique (ex. `ARCHITECTURE.md` pour `RELATIONS.md`) a changé depuis la date du sentinel → warning (drift potentiel).
3. **Édition manuelle** : si le sentinel est absent OU si le fichier a été modifié sans regen → warning ou erreur selon politique.

### Politique par défaut

| Mode | Comportement |
|------|-------------|
| `--warn` (défaut) | Warning console, exit 0 |
| `--strict` | Erreur si sentinel absent OU drift détecté, exit 2 |

### Fichiers concernés (V1)

- `RELATIONS.md` (généré par `vbb-architecture.py graph --write`)
- `AGENTS.md` (généré par `vbb-architecture.py agents --write`, cf. ADR-0012)
- `distributions/claude/CLAUDE.md` (idem)
- `distributions/pi/SYSTEM.md` (partiellement généré)

## Conséquences

### Positives
- Le drift entre source canonique et fichier généré est détecté.
- Le sentinel sert de **signature** (qui a généré, quand).
- Cohérence avec le pattern `@include` (ADR-0022) — les deux mécanismes protègent l'intégrité des entry-points.

### Négatives / coûts
- Les fichiers générés existants doivent être re-générés avec le sentinel (un seul run de bootstrap).
- Le linter ajoute une étape (mais rapide, < 1 seconde).

### Neutres
- Aucun canon direct modifié.
- Les fichiers générés peuvent rester commités (le sentinel informe les humains).

## Alternatives rejetées (≥ 2)

### Alternative A — Pas de sentinel, faire confiance aux humains
- **Description** : statu quo. Convention « do not edit » non enforced.
- **Pourquoi rejetée** : drift silencieux possible.

### Alternative B — Fichiers générés gitignorés
- **Description** : les fichiers générés ne sont pas commités, régénérés au setup.
- **Pourquoi rejetée** : complique le workflow (diff en PR ne montre pas le fichier regénéré). Le sentinel est moins invasif.

### Alternative C — Hash cryptographique (SHA256 du contenu source)
- **Description** : le sentinel inclut le hash de la source canonique.
- **Pourquoi rejetée** : trop strict (le moindre changement de formatting invalide). Le sentinel date est plus pragmatique.

## Risques

| Risque | Probabilité | Impact | Mitigation |
|--------|-------------|--------|------------|
| Les fichiers générés perdent leur sentinel au prochain edit | moyenne | faible | Le linter détecte et warning |
| Le linter est trop strict (faux positifs) | moyenne | moyen | Mode `--warn` par défaut ; itération |
| Les fichiers générés existants n'ont pas le sentinel | forte | faible | Bootstrap unique : regen une fois |

## Hypothèses

- Le format YAML/Markdown en tête de fichier est accepté par les parsers downstream.
- Le coût d'un regen est faible (les outils sont idempotents, cf. ADR-0012).
